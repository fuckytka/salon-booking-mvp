# Лінія · онлайн-запис до салону

Клієнт обирає послугу та час, створює профіль або входить, підтверджує візит і керує своїми записами. Працівник бачить завантаженість спільного розкладу та може блокувати вільний час. Один запис займає одне з трьох місць незалежно від послуги. Скасування звільняє місце й зберігає історію.

## Запуск

1. Встановіть Python 3.11 або новіший із SQLite 3.38+ та системною базою часових поясів. У Windows за потреби виконайте `py -m pip install tzdata`. На Windows у командах нижче можна замінити `python3` на `py`.
2. Розпакуйте ZIP або клонуйте репозиторій. Відкрийте термінал у папці, де лежить `server.py`.
3. Виконайте `python3 server.py`. Сервер створить локальну базу, три послуги й розклад на наступні сім днів. Дані зберігаються між запусками. Якщо порт зайнятий, виконайте `python3 server.py --port 8766`.
4. Відкрийте адресу з термінала, типово [http://127.0.0.1:8765](http://127.0.0.1:8765). Оберіть послугу, день і час. Створіть профіль із вигаданими даними, підтвердьте запис і відкрийте «Мої записи». Для зупинки сервера натисніть Ctrl+C.

## Технології та дані

HTML, CSS, JavaScript та Fetch API утворюють інтерфейс. Python обслуговує статичні файли й JSON API з одного локального порту. SQLite зберігає бронювання. Сервер приймає запити тільки на loopback. Параметри запуску передаються через CLI. Для роботи застосунку достатньо стандартної бібліотеки Python та бази часових поясів.

Час у БД і API зберігається в UTC, в інтерфейсі відображається за Києвом. Усі ціни в гривнях. Під час нового запуску розклад доповнюється до семи майбутніх днів. Параметр `--db demo.sqlite3` створює окрему базу для захисту. Паролі зберігаються як PBKDF2-хеші з випадковою сіллю. Сесійна cookie має HttpOnly і SameSite=Strict, у базі зберігається хеш токена. HTTP-журнал запитів вимкнено.

## API

Базовий шлях — `/api/v1`. Повний контракт містить схеми тіл, відповіді, права та помилки. [openapi.yaml](openapi.yaml)

| Метод | Шлях | Дія |
|---|---|---|
| GET | /services | Каталог активних послуг |
| GET | /slots?service_id=… | Вільний час, придатний до тривалості послуги |
| GET | /session | Поточний профіль або null |
| POST | /register, /login, /logout | Реєстрація, вхід, вихід |
| POST | /bookings | Створення або ідемпотентний повтор |
| GET | /bookings, /bookings/{booking_id} | Власна історія і деталі |
| PATCH | /bookings/{booking_id} | Скасування з тілом `{"status":"cancelled"}` |
| GET | /schedule | Зайнятість усіх майбутніх слотів для працівника |
| PATCH | /schedule/{timeslot_id} | Блокування або відкриття слота |

## Тестування

Для 12 інтеграційних тестів виконайте `python3 -m unittest discover -s tests -v`. Тести запускають власний HTTP-сервер на вільному порту та використовують тимчасові бази. Контрольна перевірка місткості має назву `test_06_concurrent_capacity`.

Для додаткових браузерних тестів установіть Playwright у віртуальному середовищі: `python3 -m pip install playwright`, потім `python3 -m playwright install chromium`. Виконайте `python3 tests/browser_checks.py`. Параметр `--screens ./screens` зберігає скриншоти. Застосунок працює без Playwright.

## Три сценарії для захисту

1. **Звичайний запис.** Оберіть «Стрижка», день і годину. Зареєструйте демопрофіль, натисніть «Підтвердити запис». Відкрийте «Мої записи», деталі та «Скасувати запис». Підтвердьте скасування. Для цього слота знову доступне одне місце.
2. **Помилка у формі.** У приватному вікні оберіть послугу й час. У формі створення профілю заповніть ім’я й пароль, у поле пошти введіть `invalid`. Натисніть «Створити профіль». Сервер поверне 422, фокус перейде до пошти. Виправте адресу на унікальну з доменом example.test і завершіть запис.
3. **Останнє місце.** Увійдіть одним демопрофілем, оберіть порожній слот для короткої послуги. У чотирьох вкладках дійдіть до «Підтвердження візиту» для цього самого часу. Підтвердьте перші три записи. У четвертій вкладці відкрийте інструменти розробника, вкладку Network, і підтвердьте. Покажіть відповідь на POST /bookings із HTTP 409 та кодом `slot_unavailable`. На сторінці з’явиться пояснення та кнопка «Обрати інший час». Паралельні запити різних клієнтів перевіряє T06.

## Кабінет працівника та Outbox

Зареєструйте окремий профіль без бронювань через «Мої записи» → «Створити профіль». У другому терміналі з кореня проєкту виконайте `python3 server.py --employee ВАША_ДЕМОПОШТА` для тієї самої бази. Оновіть сторінку. Працівник бачить зайнятість і може тимчасово закривати порожні слоти.

Кожне нове бронювання створює одну подію в тій самій транзакції. `python3 -m backend.dispatch` передає очікувані події в окрему локальну скриньку SQLite. Для іншого шляху вкажіть `--db` та `--inbox`. Невдала доставка отримує статус failed і повторюється наступним запуском. Отримувач усуває дублікати за event_id. Це демонстраційний транспорт E4. Реальне надсилання SMS або email потребує окремого адаптера.

Карта вимог, рішення щодо DFD та модель даних наведені у [TRACEABILITY.md](TRACEABILITY.md).
